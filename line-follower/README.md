# STM32F103C8T6 八路巡线小车（TB6612 + 74HC4051）

一套可以直接编译使用的循迹小车程序：STM32F103C8T6 主控、TB6612FNG 双路电机驱动、
基于 74HC4051 的 8 路巡线模块。采用**加权位置 + PD 差速**控制，带**上电自动校准**、
**丢线找回**和**串口实时调试**。

---

## 快速上手（TL;DR）

| 阶段 | 你要做的事 | 详见 |
|---|---|---|
| **1. 建工程** | CubeMX 生成 F103C8 底层 → 拷入本目录 6 个 `.c` / 6 个 `.h` → Keil 编译出 HEX | 第六节<br>（VS Code 用户直接看**方法 C**） |
| **2. 烧录** | Keil 勾 `Create HEX File` → BOOT0 拨到 1 复位 → FlyMcu 下载 → BOOT0 拨回 0 复位 | 第七节 |
| **3. 校准** | 上电后的 **5 秒内**把小车拿在手里，让 8 个探头**左右扫过黑线两三次** | 第八节 |
| **4. 起跑** | 3 秒倒计时 → 把车放到线上、探头压住黑线 → 自动开跑 | 第八节 |
| **5. 调参** | 只改 `board_config.h` 里的 `CTRL_KP` / `CTRL_KD` / `CTRL_BASE_SPEED` | 第九节 |

烧录后串口（115200 8N1）会一直打印这样的数据，调参全靠它：

```
N:   0   0   0 850 980 120   0   0 E:  -45 M:18 ON
     ↑ 8 个探头归一化黑度(0~1000)     ↑偏差  ↑压线掩码 在线上
```

> 每天使用的正常流程就是：**上电 → 拿车扫线 5 秒 → 放回线上 → 跑**。
> 不想每次校准的话，把 3 阶段打印出来的 `MIN:` / `MAX:` 抄进 `board_config.h`，
> 再把 `SENSOR_USE_CALIBRATION` 改成 0，以后上电直接跑。

## 二、硬件清单

| 器件 | 说明 |
|---|---|
| STM32F103C8T6 最小系统板（蓝 Pill） | 主控，HSE 8MHz 晶振，主频 72MHz |
| TB6612FNG 驱动板 | 双路电机，VM 接电池（2.5~13.5V），VCC 接 3.3V |
| 74HC4051 八路巡线模块 | 8 选 1 模拟开关，3 根地址线 + 1 路信号输出（红外板，+5V 供电） |
| 直流减速电机 ×2 | WHEELTEC 电机（自带的编码器线本程序用不到，可以不管） |

## 三、接线表

> 这张表就是程序 `board_config.h` 里的定义，**以实际接线为准**，换线请同步改两处。

### 1) 巡线传感器（74HC4051 八路红外模块）

| 模块引脚 | STM32 引脚 | 说明 |
|---|---|---|
| OUT | PA0 | 8 路探头共用的信号输出，接 ADC1_IN0 |
| A0 | PB0 | 通道地址位 0 |
| A1 | PB1 | 通道地址位 1 |
| A2 | PA1 | 通道地址位 2 |
| GND | GND | 必须共地 |

**供电**：`+5V` 走 TB6612 模块的 5V 输出。

> ⚠️⚠️ **风险提示（请务必看一眼）**：PA0 是模拟输入引脚，属于 `TTa` 类型，
> **不是 5V 容忍（FT）引脚**，输入电压不允许超过 3.3V。红外板接 5V 时，
> 它的 OUT 很可能是 5V 电平，直接送进 PA0 会经内部保护二极管持续灌电流：
> 轻则 ADC 读数不准、随转速跳动，重则永久打坏这个引脚。
>
> 两种处理办法，任选一种：
>
> | 方案 | 做法 | 代价 |
> |---|---|---|
> | **A（推荐，最省事）** | 把红外板的 `+5V` 改接到 **STM32 的 3V3** | 红外发射功率略降，探测距离短一点 |
> | **B（保留 5V 供电）** | 在 OUT 和 PA0 之间分压：`OUT —1kΩ— PA0 —1.5kΩ— GND`，5V 压到约 3.0V | 多两个电阻 |
>
> 先用万用表量一下：**红外板 OUT 对 GND 在"全白"和"全黑"两种情况下各是多少伏**，
> 只要超过 3.4V，就必须按上面处理。

### 2) TB6612FNG 驱动

| 模块引脚 | STM32 引脚 | 说明 |
|---|---|---|
| PWMA | PA8 | **TIM1_CH1**，20kHz PWM |
| AIN1 | PB12 | A 通道方向 |
| AIN2 | PB13 | A 通道方向 |
| PWMB | PA11 | **TIM1_CH4**，20kHz PWM |
| BIN1 | PB14 | B 通道方向 |
| BIN2 | PB15 | B 通道方向 |
| STBY | 3V3 | 直接接 3.3V 常高使能，**软件不控制** |
| VM（蓝色端子 +） | 电池 + 7.4V | 电机电源 |
| VM（蓝色端子 −） | 电池 − / GND | |
| VCC（3V3） | STM32 3V3 | 逻辑电源，**接 5V 会导致电平识别失败** |
| GND | GND | 必须共地 |
| AO1/AO2 | 左电机（WHEELTEC） | 对应 PWMA / AIN1 / AIN2 |
| BO1/BO2 | 右电机（WHEELTEC） | 对应 PWMB / BIN1 / BIN2 |

> 关于 PB13/PB14/PB15：这三个脚恰好是 TIM1 的互补输出 CH1N/CH2N/CH3N。
> 本程序只使能了 TIM1 的 CH1 和 CH4 正常输出，**互补输出保持关闭**，
> 所以它们就是普通 GPIO，做方向控制完全没问题。
>
> 由于 STBY 是硬件常高，**上电复位瞬间 TB6612 就是使能状态**，此时方向脚浮空。
> 建议给 AIN1/AIN2/BIN1/BIN2 各加一个 10kΩ 下拉到 GND（可选），
> 烧录和上电时也尽量把小车架起来。
>
> 另外确认一下 TB6612 模块上的 `5V` / `3V3` 是**输出**还是**输入**：
> 只接 VM 不给其它电，用万用表量这两个脚 —— 如果已经有 5V/3.3V，说明它们是板载
> 稳压器的输出（用来给主控和传感器供电的）。这种情况下**不要**再把 STM32 的 3V3
> 并上去，两个稳压器会互相倒灌；挑一路供电即可（例如由模块的 3V3 直接给 STM32 供电）。

### 3) 其它

| 功能 | 引脚 | 说明 |
|---|---|---|
| 板载 LED | **PA4** | 高电平点亮（`LED_ACTIVE_LOW = 0`） |
| 串口 TX | PA9 → USB-TTL 的 RX | 调试打印 + FlyMcu 下载 |
| 串口 RX | PA10 → USB-TTL 的 TX | 同上 |

> TIM1 的 CH2/CH3 默认也落在 PA9/PA10 上，但本程序没有使能这两个通道，
> 所以 USART1 可以正常使用，互不干扰。

## 四、74HC4051 是怎么"调用 8 个传感器"的

74HC4051 是一片 8 选 1 模拟开关。单片机用 3 根 IO 送地址，选中某一路探头，
被选中探头的信号就从公共端输出到 PA0，ADC 采回来后换下一个地址。

| A2 | A1 | A0 | 选中探头 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 0 | 0 | 1 | 1 |
| 0 | 1 | 0 | 2 |
| 0 | 1 | 1 | 3 |
| 1 | 0 | 0 | 4 |
| 1 | 0 | 1 | 5 |
| 1 | 1 | 0 | 6 |
| 1 | 1 | 1 | 7 |

（对应本车接线：A2 = PA1、A1 = PB1、A0 = PB0）

采样流程（`line_sensor.c` 里的 `ReadChannel()`）：

1. 送出该探头的 3 位地址；
2. 等 `SENSOR_SETTLE_US`（默认 50µs）让 4051 输出和模块上的 RC 稳定；
3. **丢弃第一次转换**（切换瞬间的值不可信），再连采 `SENSOR_OVERSAMPLE`（默认 4）次取平均。

一轮 8 路扫描约 0.6ms，控制周期 5ms，完全够用。

## 五、算法说明

### 1) 归一化

每个探头单独校准出"最白"读数 `min` 和"最黑"读数 `max`，把原始 ADC 值映射成 0~1000 的"黑度"：

```
// 黑线读数 > 白底读数（SENSOR_BLACK_IS_HIGH = 1）
norm = (raw - min) * 1000 / (max - min)

// 黑线读数 < 白底读数（SENSOR_BLACK_IS_HIGH = 0）★ 本车用这个
norm = (max - raw) * 1000 / (max - min)
```

> 本车实测是第二种：**压黑线时读数反而更小**，所以 `SENSOR_BLACK_IS_HIGH = 0`。
> 如果这里设反了，归一化出来的"黑度"就是倒的 —— 表现为**白地被当成黑线**
> （串口里看到白底上 `N:` 全是 1000）。

这样即使 8 个探头的亮度、增益有差异（模块上很常见），也能公平比较。

### 2) 位置偏差（加权平均）

```
位置  pos[i] = i*2 - 7          // 最左 -7，最右 +7，步进 2
偏差  error  = Σ(norm[i]*pos[i]) / Σ(norm[i]) * 100      // -700 ~ +700
```

只有"黑度 ≥ `SENSOR_ACTIVE_LEVEL`"的探头参与计算。好处是线压在两探头之间时
也能给出连续的小数级偏差（亚探头精度），比"8 个开关量查表"平滑得多，不容易一抖一抖。

`error < 0` 表示线在左边，`error > 0` 表示线在右边。

### 3) 三状态控制

控制逻辑是一个状态机，**状态下 ② ③ 的前进分量都是 0**（只原地转）：

| 状态 | 触发条件 | 输出 |
|---|---|---|
| ① `ST_FOLLOW` 正常循迹 | `\|error\| < 520` | `左轮 = BASE + turn`，`右轮 = BASE - turn`（PD 差速，边走边修） |
| ② `ST_CORNER` 直角弯 | `\|error\| >= 520`（线压到最外侧两个探头） | `左轮 = ±PIVOT`，`右轮 = ∓PIVOT`（一个正转一个反转，**绕中心原地旋转**） |
| ③ `ST_SEARCH` 丢线 | 8 路全白 | 朝最后看到线的方向原地转，超时 2s 停车 |

**② 直角弯原地转**是这段代码的关键：

```
左轮 = +0.40  右轮 = -0.40    → 车绕自身中心顺时针（右）旋转
左轮 = -0.40  右轮 = +0.40    → 反方向（左）旋转
```

两轮**速度大小相等、方向相反**，合力矩让车原地打转，合外力为 0，所以**前进分量为零**。
这样遇到 90° 直角弯时，车会在弯口停下来"拧"过去，而不是靠惯性冲过头。

#### 四条保证"左右都能拐"的规则

| 规则 | 为什么必须有 |
|---|---|
| **进入时锁存方向**（`s_corner_dir`），整个拐弯过程不变 | 否则中途一抖就改主意 |
| **拐弯途中丢线也继续朝锁定方向转** | 转过中线的那一刻如果改看"最后看到线的方向"，会判成反方向，变成反向打圈 |
| **退出阈值 `CTRL_SHARP_TURN_EXIT = 220`**，必须远小于进入阈值 520 | ★这是"右直角只会往左拐"的根因★ 原来退出阈值用 400 太松：车还没转够就退出 → PD 一修又把线甩到另一侧、`\|error\|` 再次超 520 → 这次以**左侧**重新进入拐弯 → 锁存成向左 |
| **拐完后 100ms 冷却**（`CTRL_CORNER_SETTLE_MS`）+ **单次拐弯 1200ms 超时**（`CTRL_CORNER_MAX_MS`） | 冷却防连触发；超时防止原地转圈出不来 |

`PIVOT` 之外的 PD 部分：线偏右 → `turn > 0` → 左轮快、右轮慢 → 车头右转回到线上。
巡线一般只用 PD，`Ki` 保持 0 即可（代码里留着方便以后加）。

#### 调试输出

每次进出拐弯，串口会打印一行（`DEBUG_UART = 1` 时）：

```
CORNER R  err=640 mask=C0      ← 锁定向右拐，偏差 +640，压线掩码 0xC0（最右两个探头）
corner done                    ← 线回到正中，拐弯完成
corner timeout                 ← 转太久放弃（多半卡住或线对着探头边缘）
```

**`CORNER R` 还是 `CORNER L` 是判断方向逻辑对不对的关键**：
如果右直角弯时打印的是 `CORNER L`，说明问题在更上游（传感器左右顺序 / 极性），
而不是拐弯逻辑。

### 4) 丢线处理

- 8 路都看不到线时，记录进入丢线的时刻，然后**朝最后一次看到线的方向原地转**
  （`CTRL_SEARCH_SPEED`，同样不前进）；
- 超过 `CTRL_LOST_STOP_MS`（默认 2s）仍找不到 → 停车保护，避免小车冲出去；
- 十字路口/交叉：8 路同时压黑时加权平均自然接近 0，车会直行通过，不用特殊处理
  （但如果四个方向都是粗黑块，`|error|` 可能偏大而误判成急弯，可按第九节微调阈值）。

## 六、建立工程（Keil 或 VS Code）

### 方法 A（推荐：CubeMX 生成底层 + 本代码）

1. 安装 Keil MDK5 和 `Keil.STM32F1xx_DFP` 器件包；
2. STM32CubeMX 新建工程，选 `STM32F103C8Tx`，按下面的清单配置，时钟树设 HSE 8MHz → 72MHz，
   工具链选 `MDK-ARM V5`，生成代码：

   | 外设 | 配置 |
   |---|---|
   | PA0 | ADC1_IN0（Analog） |
   | PA1 / PB0 / PB1 | GPIO_Output（74HC4051 地址线 A2/A0/A1） |
   | PA8 | TIM1 CH1 → PWM Generation CH1 |
   | PA11 | TIM1 CH4 → PWM Generation CH4 |
   | PA9/PA10 | USART1 Asynchronous，115200 |
   | PB12/PB13/PB14/PB15 | GPIO_Output（TB6612 方向脚） |
   | PA4 | GPIO_Output（LED，高电平点亮） |
   | SYS | Debug = Serial Wire |
   | TIM1 | Prescaler 0，Counter Period 3599（20kHz） |

   > 注意：**不要**在 CubeMX 里勾选 TIM1 的 CH1N/CH2N/CH3N，它们会占用 PB13/PB14/PB15。

3. 把本目录 `Core/Inc/*.h` 复制进生成的 `Core/Inc`，`Core/Src/*.c` 复制进 `Core/Src`；
4. 用本目录的 `main.c` **覆盖**生成的 `main.c`（引脚配置与上表完全一致）。
   若想保留 CubeMX 生成的 `main.c`，就把 `main()` 里的流程搬到 `USER CODE` 段即可，
   此时可删掉本目录 `main.c` 里的 `MX_*_Init()` 和 `HAL_MspInit()`，用 CubeMX 生成的；
5. Keil 里把这 5 个 `.c` 加入工程分组（`stm32f1xx_it.c` 用 CubeMX 生成的即可，
   只要里面有 `SysTick_Handler()` 调用 `HAL_IncTick()`）；
6. 编译、下载。

### 方法 B（完全用本代码）

新建空工程 → RTE 勾选 `CMSIS Core`、`Device Startup`、`STM32F1xx HAL` 的
`RCC / GPIO / ADC / TIM / UART / CORTEX / FLASH` 及 `CMSIS` 组件，
再把本目录 13 个文件全部加入工程编译。

> 串口打印用的是 `vsnprintf + HAL_UART_Transmit`，**不需要**重定向 `printf` / `fputc`。
> 建议在 Keil 的 `Options for Target → Target` 里勾上 **Use MicroLIB**（体积小，最省事）。

### 方法 C（VS Code + PlatformIO：不用 Keil，也不用 CubeMX）

PlatformIO 会自动下载 `arm-none-eabi-gcc` 工具链和 STM32Cube F1 库，点一下按钮就编译出 HEX，
然后照样用 FlyMcu 烧录。本目录里已经放好了 `platformio.ini`。

1. VS Code 装扩展 **PlatformIO IDE**（装完要重启 VS Code）；
2. 用 VS Code **打开 `line-follower` 这个文件夹**（不是打开里面的 `Core`）；
3. `platformio.ini` 已经把源码目录指向 `Core/Src`、头文件目录指向 `Core/Inc`，
   **同一套代码 Keil 和 VS Code 共用，不用复制**；
4. 首次编译会联网下载工具链和 STM32Cube 包（约 200~400MB），耐心等；
5. 点底部状态栏的 **✓ Build**，产物在 `.pio/build/bluepill_f103c8/firmware.hex`；
6. 看串口：点状态栏的 **🔌 Serial Monitor**（波特率已在 `platformio.ini` 里设成 115200）。
   它和 FlyMcu 抢同一个 COM 口，**烧录前先把监视器关掉**。

> - 首次编译完成前，编辑器里 `#include "stm32f1xx_hal.h"` 会报红波浪线，属正常现象，
>   编译一次让 PlatformIO 把库装好就消失了。
> - 状态栏那个 **→ Upload** 按钮是给 ST-Link 用的，你用 FlyMcu，不用点。
> - 想以后换成 ST-Link 一键下载兼调试，把 `platformio.ini` 末尾两行取消注释即可。

## 七、用 FlyMcu 烧录（串口 ISP）

FlyMcu 走的是 STM32 出厂内置的串口 BootLoader，用的是 **USART1（PA9/PA10）**，
正好和本程序的调试串口是同一组引脚 —— 一个 USB-TTL 模块既能下载又能看调试输出。

### 1) Keil 生成 HEX 文件

`Options for Target → Output` 勾选 **Create HEX File**，重新编译。
产物在工程目录的 `Objects\<工程名>.hex`（FlyMcu 也可以直接烧 `.bin`，但 HEX 更省事）。

顺便核对一下 `Options for Target → Target`：

| 项目 | 正确值（STM32F103C8T6） |
|---|---|
| IROM1 | Start `0x8000000`，Size `0x10000`（64KB） |
| IRAM1 | Start `0x20000000`，Size `0x5000`（20KB） |
| Use MicroLIB | 勾上 |

### 2) 接线

| USB-TTL | 蓝 Pill |
|---|---|
| TXD | PA10（RX） |
| RXD | PA9（TX） |
| GND | GND |
| 3V3 | 3V3（如果板子已由电池供电，就不用接） |

> 如果用的是 5V 的 USB-TTL，PA9/PA10 都是 5V 容忍引脚，可以直接接；
> 但 **3V3 那根线不要接**，避免和板上稳压器互相倒灌。

### 3) 进入 BootLoader

蓝 Pill 上有一个 `BOOT0` 跳线帽（旁边通常标 `0 / 1`）：

1. 跳线帽从 `0` 挪到 **`1`**（BOOT1/PB2 保持 0 即可，本程序没用 PB2）；
2. 按一下 **RESET** 键（或重新上电）—— 此时单片机停在 BootLoader，程序不运行；
3. 打开 FlyMcu，选择 USB-TTL 对应的 **COM 口**，波特率填 **115200**（求稳就用它，
   460800 也行但有些廉价 USB-TTL 会丢包）；
4. 点「读器件信息」，能读出芯片 ID / Flash 容量就说明通信正常；
5. 「选择文件」选 `Objects\<工程名>.hex`；
6. 勾上 **校验**；不要动 **读保护 / 写保护** 之类的选项；
7. 点 **开始编程**，等进度到 100% 并提示成功。

> 关于「编程后执行」：勾上它，烧完程序会立刻跑起来。本程序有 `WAIT_FOR_LINE_ON_START`
> 保护（不压到黑线不动），所以即使勾了也不会冲出桌面；但**校准窗口只有上电后那 5 秒**，
> 勾了它就没时间拿着小车扫线。所以建议：**先不勾「编程后执行」**，烧完按下面的步骤
> 手动复位，从校准开始完整走一遍流程。

### 4) 回到运行模式（最容易忘的一步）

1. 把 **BOOT0 跳线帽挪回 `0`**；
2. 按一下 RESET。

⚠️ 烧完不把 BOOT0 挪回 `0`，程序永远不会运行 —— 现象是"下载成功但小车毫无反应"，
新手十有八九卡在这里。

### 5) 烧录时的注意事项

- **烧录前把小车架起来、或者断开电机电源（VM）**：复位瞬间引脚是浮空输入，
  不同 TB6612 模块对 STBY 的处理不同，避免轮子突然抽一下把车带跑；
- FlyMcu 会**独占串口**：要在串口助手/FlyMcu 之间切换，先把上一个工具的串口关掉，
  否则报"串口打开失败"或"无法连接"；
- 烧完以后同一根 USB-TTL 不要拔，直接用串口助手（115200 8N1）就能看到
  本程序打印的 `N:... E:...` 调试数据（前提是 `DEBUG_UART = 1`）；
- 「无法连接，请检查连接和串口」的排查顺序：
  BOOT0 是不是 1 → 移动跳线后有没有按 RESET → COM 口选对没有 →
  TX/RX 是不是接反了 → 有没有共地 → 电机电源有没有干扰到 3.3V。

## 八、上电流程与第一次测试

1. **把小车架起来（轮子悬空）**，再上电；
2. 若 `SENSOR_USE_CALIBRATION = 1`：上电后有 **5 秒校准时间**（LED 每 100ms 闪一次）。
   这 5 秒里把小车拿在手里，让 8 个探头**从左到右缓慢扫过黑线两三次**，
   保证每个探头都既压过白底、又压过黑线；
3. 校准结束串口会打印 `MIN:` / `MAX:`，可以抄进 `board_config.h` 的默认表，
   以后把 `SENSOR_USE_CALIBRATION` 改成 0 就不必每次校准；
4. 之后是 **3 秒倒计时**，把小车放到线上（探头跨在黑线上，尽量居中）；
5. 若 `WAIT_FOR_LINE_ON_START = 1`（默认）：倒计时结束后小车**不会立刻跑**，
   LED 闪烁、串口打印 `Waiting for the line...`，等探头真的压到黑线后自动起跑。
   这样刚烧录完或刚上电时，没人扶的小车也不会自己冲出去；
6. 串口打印 `GO!` 后开始跑。

**方向自检**：把黑线放在**最左边探头**下面，正确的话应该是"左轮慢、右轮快"（车向左修正）。
如果反了，把 `board_config.h` 里的 `SENSOR_ORDER_REVERSED` 改成 1。
（如果只是某个轮子转反，改 `MOTOR_A_INVERT` / `MOTOR_B_INVERT`。）

**串口数据怎么读**：

```
N:   0   0   0 850 980 120   0   0 E:  -45 M:18 ON
    ↑ 8 个探头归一化黑度(0~1000)      ↑偏差   ↑压线掩码
```

`E` 负数是线偏左、正数是线偏右；`M` 十六进制，bit0 是最左探头；结尾 `ON`/`LOST` 表示是否压线。

## 九、调参指南（都在 `board_config.h`）

| 现象 | 怎么调 |
|---|---|
| 直道上左右画龙、来回摆 | 加大 `CTRL_KD`（1.2 → 1.8）；还不行就减小 `CTRL_KP` |
| 入弯反应慢、直接冲出去 | 加大 `CTRL_KP`；同时降低 `CTRL_BASE_SPEED` |
| 高频抖动 / 电机嗡嗡发抖 | 减小 `CTRL_KD`；检查相邻通道是否串扰，加大 `SENSOR_SETTLE_US` |
| 跑得太慢、太保守 | 提高 `CTRL_BASE_SPEED`（0.50 → 0.60 是上限，再快弯道会滑出去） |
| 电机不转，只听到细微嗡嗡声 | 加大 `CTRL_MIN_DUTY`（0.16 → 0.22） |
| 修正方向完全相反 | 改 `SENSOR_ORDER_REVERSED` 为 1 |
| 出弯后回不到线上、总是过冲 | 加大 `CTRL_KD`，或减小 `CTRL_TURN_LIMIT` |
| 容易丢线 | 减小 `CTRL_BASE_SPEED`；检查探头离地高度（一般 5~15mm）；加大 `SENSOR_ACTIVE_LEVEL` 的容错（可降到 200） |
| **直角弯拐不过去、冲过头** | 说明原地转触发太晚：把 `CTRL_SHARP_TURN_ERROR` 从 520 **降到 420~460**；或把 `CTRL_BASE_SPEED` 再降到 0.30 |
| **正常小弯也停下原地转、走得很犹豫** | 触发太早：把 `CTRL_SHARP_TURN_ERROR` **升到 580~620** |
| **拐弯时原地抽搐、来回抖** | 退出阈值 `CTRL_SHARP_TURN_EXIT` 太大（降到 180），或 `CTRL_PIVOT_SPEED` 太大（降到 0.32） |
| **直角弯总是往同一边拐** | 先看串口打印的 `CORNER R` / `CORNER L`：打印的方向本身就不对 → 查 `SENSOR_ORDER_REVERSED`；打印对但车拐错 → 查两个轮子的方向 |
| **拐弯转太久才出来、甚至超时** | `CTRL_SHARP_TURN_EXIT` 调大一点（220 → 260），或加大 `CTRL_PIVOT_SPEED` |
| 拐弯时转速不够、转不动 | 加大 `CTRL_PIVOT_SPEED`（0.40 → 0.50），但要小于死区之上能稳定转动的值 |

调试顺序建议：**先架空确认方向 → 低速跑通 → 再逐步加 KP → 加 KD → 最后加速度**，一次只改一个参数。

调好车以后把 `DEBUG_UART` 设为 0（串口打印是阻塞的，会轻微拖慢控制循环）。

## 十、常见问题

| 现象 | 排查 |
|---|---|
| 串口完全没输出 | PA9→TTL 的 RX 是否接反、波特率 115200、是否共地、`DEBUG_UART` 是否为 1 |
| 8 个归一化值全是 0 或全是 1000 | 校准没扫到线；模块没供电；OUT 没接到 PA0；`SENSOR_BLACK_IS_HIGH` 设反 |
| 数值乱跳 | 没共地、电机干扰（传感器与电机电源分开走线并在模块 VCC 加 100nF）、`SENSOR_SETTLE_US` 太小 |
| 电机完全不转 | STBY 是不是真的接到 3.3V 了；`VM` 有没有电池电压；`CTRL_MIN_DUTY` 太小；PA8/PA11 有没有被别的功能占用 |
| 只有一个轮子转 | 对应通道的 AIN1/AIN2 或电机线没接好 |
| 上电电机狂冲 | 先确认 `TB6612_Init()` 里 STBY 是最后才拉高的；主控与驱动共地；不要带电插拔电机线 |
| 车往一个方向一直转（丢线不回来） | `SENSOR_ORDER_REVERSED` 设错，导致丢线时朝反方向找 |
| **放在地上就原地打转、走不了直线** | 见下面「小车原地打转怎么查」 |
| 走起来画龙、左右摆 | `CTRL_KD` 太小或 `CTRL_KP` 太大，按第九节调 |
| 串口打印 `VALID: 0 0 ...` | 校准那 5 秒没扫到黑线，重新上电、按要求左右扫线 |
| 车在十字路口乱转 | 十字处 8 路全黑，加权平均应接近 0；若乱转说明有探头校准不良，检查 `VALID` 是否为 1 |

### 小车原地打转怎么查（三步定位）

"走不了直线、原地打转"只有三个源头，按下面顺序做，每步都能排除一类问题。

**第 1 步：看串口，判断传感器（不用动硬件）**

把小车放在线上，看 `N:` 那 8 个数：

| 你看到的 | 说明 | 怎么办 |
|---|---|---|
| 压线的位置是 900~1000、别处接近 0 | 传感器正常 ✅ | 去做第 2 步 |
| 8 个数**全是 0** | 探头没看到线（离地太高 / 极性反 / 校准失败） | 先看串口的 `VALID:`，全 0 就重新上电认真扫线；`VALID` 正常就改 `SENSOR_BLACK_IS_HIGH` |
| 8 个数**全是 1000 左右** | 极性反了，白底被当成黑线 | 把 `SENSOR_BLACK_IS_HIGH` 改成 0（原来是 1） |

**第 2 步：架空做直行测试，判断电机**

把车架空（轮子悬空），**上电前**先把 `board_config.h` 里改成：

```c
#define MOTOR_SELF_TEST   1
```

烧录后上电，串口会依次提示三段，按提示看轮子：

| 阶段 | 正常现象 | 不对的话 |
|---|---|---|
| `1) both wheels forward` | 两个轮子都朝**车前进**方向转，且转速差不多 | 有一个往后转 → 改 `MOTOR_A_INVERT` 或 `MOTOR_B_INVERT` |
| `2) LEFT wheel only` | **左**轮朝前转 | 不动 → 电机线/接线问题 |
| `3) RIGHT wheel only` | **右**轮朝前转 | 同上 |

三项都正常，说明电机和接线没问题 —— 排完记得把 `MOTOR_SELF_TEST` 改回 **0**。

**第 3 步：架空做方向测试，判断传感器顺序**

保持架空，上电走完流程后，用一小片黑纸（或把小车摆到线上让车不动）贴在**最左边探头**下面，
看两个轮子：

| 现象 | 结论 |
|---|---|
| **左轮慢/反转、右轮快** | 正确 ✅（车要向左修正） |
| **左轮快、右轮慢/反转** | 反了 → 把 `SENSOR_ORDER_REVERSED` 改成 1 |

三步都正常却还是打转，再回去查：校准有没有认真做（`VALID` 全 1 吗）、探头离地高度（5~15mm）、
电池电压够不够（电压低时一个轮子可能根本转不动，表现就是原地打转）。

## 十一、换成别的巡线模块怎么改

**情况 1：模块是比较器输出（OUT_D 数字引脚，只有一个 IO 表示"当前选中的探头是否在线上"）**

把 `line_sensor.c` 的 `AdcReadOnce()` 换成读 GPIO，并把归一化结果直接定成 0 / 1000：

```c
static uint16_t ReadChannel(uint8_t ch)
{
    SelectChannel(ch);
    Board_DelayUs(SENSOR_SETTLE_US);
    return (HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_5) == GPIO_PIN_SET) ? 1000U : 0U;
}
```
（此时 `min`/`max` 校准没用了，把 `SENSOR_USE_CALIBRATION` 设为 0。）

**情况 2：8 路各自独立数字输出的模块（8 个 IO，占 PA0~PA7 之类）**

不需要 4051，也不用 ADC，直接一次读 8 个引脚：

```c
static const uint16_t s_pin[SENSOR_NUM] = {
    GPIO_PIN_0, GPIO_PIN_1, GPIO_PIN_2, GPIO_PIN_3,
    GPIO_PIN_4, GPIO_PIN_5, GPIO_PIN_6, GPIO_PIN_7
};

void LineSensor_Scan(LineSensor_t *s)
{
    /* 其余统计逻辑与现成的 Scan 完全一样，只是数据来源换成 8 个 IO */
    for (uint8_t i = 0; i < SENSOR_NUM; i++) {
        uint8_t black = (HAL_GPIO_ReadPin(GPIOA, s_pin[i]) == GPIO_PIN_SET);
        s->raw[i]  = black ? 4095U : 0U;
        s->norm[i] = black ? (SENSOR_BLACK_IS_HIGH ? 1000U : 0U)
                           : (SENSOR_BLACK_IS_HIGH ? 0U : 1000U);
    }
    /* 下面照抄原来 Scan 里从 sum_w 开始的部分 */
}
```

**情况 3：想换探头顺序或加探头**：只改 `board_config.h` 的 `SENSOR_NUM`、
`SENSOR_ORDER_REVERSED` 和 `board_config.h`/`line_sensor.c` 里的地址线即可，
`motor_control.c` 不用动。

## 十二、可以继续扩展的方向

- 用 Flash 保存校准值（F103C8 最后一页 `0x0800FC00`），省掉每次上电校准；
- 加入编码器 / 霍尔测速，把基础速度做成闭环（当前是纯开环占空比）；
- 识别路口：`SENSOR_ACTIVE_LEVEL` 命中 6 路以上判为十字/丁字，做计路口逻辑；
- 加 OLED + 按键，脱离电脑改参数。
